# 一个 agent loop，就是反复问"还有活吗"

DeepSeek Harness 的 agent runtime 有 893 行。

但它的骨架只有三层 `while`。

这个仓库把那个骨架从零写了一遍——九个文件，每个都能直接跑，输出会打印出和真实代码一样的调用顺序。读完它，你再打开 `agent.ts`，看到的不会是 893 行代码，而是一直在问同一个问题的三层循环，外加一堆出口条件。

## 那 893 行是怎么来的

三层循环本身加起来不到 30 行。

剩下 860 行全在处理"活"的边界情况：

- 用户连发三条消息，怎么决定先处理哪条、什么时候开新的一轮
- 模型说要调工具，那这一轮就还不能结束
- 网络断了，重发一次算不算新的一轮
- 用户点了停止，已经显示在屏幕上的半句话怎么办
- 重启之后，还没处理的排队消息还在不在

这些都不是循环结构的问题，是**出口条件**的问题。

所以这个仓库的重点从来不是"怎么写 while"，而是每一层的循环到底在等什么、什么时候可以停。
